# Feature Specification: Career History

**Feature Branch**: `005-career-history`
**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 취업 준비 기록 및 히스토리 조회 (Priority: P1)

> 사용자는 플랫폼에서 수행한 취업 준비 활동 기록을 다시 확인하기 위해 취업 준비 히스토리를 조회한다.

**Acceptance Scenarios**:
1. **Given** 사용자가 취업 준비 기록 페이지에 접근했을 때, **When** 저장된 기록 데이터가 존재하면, **Then** 날짜별 또는 기업별 취업 준비 기록이 목록으로 표시된다.
2. **Given** 사용자가 기록 목록을 보고 있을 때, **When** 특정 기록의 상세보기 버튼을 클릭하면, **Then** 해당 기록의 상세 페이지로 이동한다.
3. **Given** 저장된 취업 준비 기록이 없을 때, **When** 사용자가 기록 페이지에 접근하면, **Then** 기록이 없다는 안내 메시지가 표시된다.

---

### User Story 2 - 면접 연습 기록 저장 및 조회 (Priority: P1)

> 사용자는 과거에 수행한 텍스트 또는 비디오 모의면접 기록을 다시 확인하여 자신의 답변과 AI 피드백을 복기한다.

**Acceptance Scenarios**:
1. **Given** 사용자가 면접 연습을 완료했을 때, **When** 결과 데이터가 생성되면, **Then** 전체 스크립트, 면접 질문, 사용자 답변, AI 피드백이 저장된다.
2. **Given** 사용자가 면접 연습 기록 상세 페이지에 접근했을 때, **When** 저장된 면접 데이터가 존재하면, **Then** 질문-답변 매칭 데이터와 AI 피드백이 표시된다.
3. **Given** AI가 개선이 필요한 답변을 분석했을 때, **When** 사용자가 상세 기록을 확인하면, **Then** 오답 또는 개선 필요 답변이 하이라이팅되어 표시된다.

---

### User Story 3 - 누적 데이터 기반 AI 역량 평가 확인 (Priority: P1)

> 사용자는 누적된 서류 점수와 면접 점수를 기반으로 자신의 취업 역량 수준과 약점을 확인한다.

**Acceptance Scenarios**:
1. **Given** 사용자의 누적 취업 준비 데이터가 존재할 때, **When** 역량 평가 영역을 확인하면, **Then** 서류 점수, 면접 점수, 종합 점수가 표시된다.
2. **Given** 점수 변화 데이터가 존재할 때, **When** 사용자가 성장 흐름을 확인하면, **Then** 점수 변화 추이가 그래프 또는 통계 형태로 표시된다.
3. **Given** 약점 분석 데이터가 존재할 때, **When** 사용자가 역량 평가 결과를 확인하면, **Then** 보완이 필요한 역량과 우선 학습 타겟이 표시된다.

---

### User Story 4 - 맞춤형 로드맵 가이드 확인 (Priority: P2)

> 사용자는 누적된 취업 준비 기록과 약점 분석을 기반으로 앞으로의 학습 방향과 취업 준비 액션 플랜을 확인한다.

**Acceptance Scenarios**:
1. **Given** 사용자의 취업 준비 기록과 분석 데이터가 존재할 때, **When** 로드맵 페이지에 접근하면, **Then** 단계별 취업 준비 로드맵이 표시된다.
2. **Given** 사용자의 약점 분석 결과가 존재할 때, **When** 로드맵을 확인하면, **Then** 약점을 보완하기 위한 추천 학습 항목이 표시된다.
3. **Given** 분석 가능한 누적 데이터가 부족할 때, **When** 사용자가 로드맵 페이지에 접근하면, **Then** 추가 기록이 필요하다는 안내 메시지가 표시된다.

---

### Edge Cases

- 취업 준비 기록 데이터가 없을 경우 어떤 빈 상태 UI를 보여줄 것인가?
- 면접 스크립트 또는 질문-답변 매칭 데이터가 일부 누락된 경우 어떻게 표시할 것인가?
- AI 피드백 데이터가 없는 경우 기본 안내 문구를 표시할 것인가?
- 서류 점수와 면접 점수 중 일부만 존재할 경우 종합 점수를 어떻게 표시할 것인가?
- 누적 데이터가 부족한 경우 맞춤형 로드맵을 생성하지 않고 어떤 안내를 보여줄 것인가?
- 존재하지 않는 기록 상세 페이지에 접근했을 때 어떻게 처리할 것인가?

## Requirements

### Functional Requirements

- **FR-001**: 시스템은 사용자의 취업 준비 기록을 날짜별 또는 기업별로 조회할 수 있어야 한다.
- **FR-002**: 시스템은 텍스트 또는 비디오 모의면접의 전체 스크립트를 저장하고 조회할 수 있어야 한다.
- **FR-003**: 시스템은 면접 질문과 사용자 답변의 매칭 데이터를 표시해야 한다.
- **FR-004**: 시스템은 AI가 분석한 오답 및 개선 피드백 데이터를 표시해야 한다.
- **FR-005**: 시스템은 취업 준비 기록을 RDB 엔티티 구조로 저장하고 재조회할 수 있어야 한다.
- **FR-006**: 시스템은 누적된 서류 점수와 면접 점수를 기반으로 AI 역량 종합 평가를 제공해야 한다.
- **FR-007**: 시스템은 누적 점수 데이터를 그래프 또는 통계 형태로 표시해야 한다.
- **FR-008**: 시스템은 사용자의 약점을 분석하여 우선 학습 타겟을 제공해야 한다.
- **FR-009**: 시스템은 약점 보완을 위한 맞춤형 취업 준비 로드맵을 제공해야 한다.
- **FR-010**: 시스템은 백엔드 API 연결 전까지 mock data를 사용하여 화면을 구성할 수 있어야 한다.

### Key Entities

- **CareerHistory**:
  - `id`: 취업 준비 기록 고유 ID
  - `userId`: 사용자 ID
  - `companyName`: 기업명
  - `activityType`: 활동 유형
  - `title`: 기록 제목
  - `practiceDate`: 연습 날짜
  - `status`: 진행 상태
  - `score`: 점수
  - `summary`: 기록 요약

- **InterviewPracticeHistory**:
  - `id`: 면접 연습 기록 고유 ID
  - `careerHistoryId`: 취업 준비 기록 ID
  - `interviewType`: 면접 유형
  - `script`: 전체 면접 스크립트
  - `question`: 면접 질문
  - `answer`: 사용자 답변
  - `highlightedIssue`: AI가 표시한 문제 답변
  - `feedback`: AI 개선 피드백

- **CareerCompetencyReport**:
  - `id`: 역량 평가 리포트 ID
  - `userId`: 사용자 ID
  - `documentScore`: 서류 분석 점수
  - `interviewScore`: 면접 분석 점수
  - `totalScore`: 종합 점수
  - `weaknesses`: 약점 목록
  - `priorityTargets`: 우선 학습 타겟
  - `growthTrend`: 점수 변화 데이터

- **CareerRoadmap**:
  - `id`: 로드맵 ID
  - `userId`: 사용자 ID
  - `step`: 로드맵 단계
  - `title`: 단계 제목
  - `description`: 단계 설명
  - `recommendedActions`: 추천 액션 플랜
  - `targetSkill`: 보완 대상 역량

## Success Criteria

- **SC-001**: 사용자는 날짜별 또는 기업별 취업 준비 기록 목록을 확인할 수 있다.
- **SC-002**: 사용자는 과거 텍스트 또는 비디오 모의면접의 전체 스크립트와 질문-답변 데이터를 확인할 수 있다.
- **SC-003**: 사용자는 AI가 하이라이팅한 오답과 개선 피드백을 확인할 수 있다.
- **SC-004**: 사용자는 누적 서류 점수와 면접 점수를 기반으로 한 AI 역량 평가를 확인할 수 있다.
- **SC-005**: 사용자는 그래프 또는 통계 형태로 점수 변화 흐름을 확인할 수 있다.
- **SC-006**: 사용자는 약점 보완을 위한 우선 학습 타겟과 맞춤형 로드맵을 확인할 수 있다.
- **SC-007**: 데이터가 없거나 일부 누락되어도 화면이 깨지지 않고 안내 메시지가 표시된다.
- **SC-008**: 기존 사용자 페이지와 관리자 페이지의 동작에 영향을 주지 않는다.

## Assumptions

- Career History는 사용자 페이지 기준 기능으로 구현한다.
- 적용 모듈은 `user-backend`, `user-frontend`를 기준으로 한다.
- 현재 프론트엔드 구현 단계에서는 백엔드 API가 완성되지 않았을 수 있으므로 mock data를 우선 사용한다.
- 실제 RDB 저장 및 조회 기능은 백엔드 API 명세가 확정된 후 연동한다.
- 로그인 인증 및 권한 검증은 기존 인증 구조를 따른다.
- 관리자 페이지, FastAPI 모델 서빙 구조, 공통 인프라 설정은 현재 작업 범위에서 제외한다.
