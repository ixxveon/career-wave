# Checklist: 사용자 채용 공고

> tasks.md가 "무엇을 만들지"라면, 이 파일은 "제대로 만들어졌는지" 검증한다. 구현 완료 후 PR 전 본인이 직접 체크한다.

## Phase 1 - 계약 및 타입

- [ ] 구현 PR 브랜치가 `feature/user-jobNotice-contract-types` 또는 같은 패턴의 Phase 전용 브랜치다.
- [ ] `api-schema.md`의 목록 응답 필드와 `JobNoticeTypes.ts`의 화면 필드가 매핑되어 있다.
- [ ] `api-schema.md`의 상세 응답 필드와 상세 드로어 표시 필드가 매핑되어 있다.
- [ ] API 응답 계약이 `ApiResponse<T>`의 `success`, `statusCode`, `message`, `data` 필드를 기준으로 작성되어 있다.
- [ ] 목록과 상세가 같은 공고 ID와 스크랩 상태를 공유한다.
- [ ] 필터와 정렬 값은 화면 라벨, API 쿼리 값, 내부 상수 사이의 변환 규칙이 명확하다.
- [ ] `전체` 필터는 API 요청에서 생략하거나 서버가 전체 조건으로 해석한다.

## Phase 2 - 목록 조회와 탐색 조건

- [x] 구현 PR 브랜치가 `feature/user-jobNotice-list-flow` 또는 같은 패턴의 Phase 전용 브랜치다.
- [x] 최초 진입 시 로딩 또는 목록이 사용자에게 명확히 표시된다.
- [x] 목록 API 호출은 `frontend/src/user/api` 하위 모듈을 통해 수행된다.
- [x] 페이지 또는 컴포넌트에서 `axios`나 `fetch`를 직접 호출하지 않는다.
- [x] API 연동 시 서버 상태는 TanStack Query 사용을 우선 검토했거나, 사용하지 않은 이유가 남아 있다.
- [x] API 성공, 빈 결과, 오류 상태가 서로 다른 UI 메시지를 가진다.
- [x] 결과 헤더의 공고 수와 실제 카드 개수가 일치한다.
- [x] 통계 카드의 전체 공고 수와 오늘 신규 공고 수가 API 또는 mock 응답 기준으로 표시된다.
- [x] 검색 버튼 클릭과 Enter 입력이 같은 결과를 만든다.
- [x] 인기 검색어 클릭 시 검색 input 값과 목록 결과가 함께 갱신된다.
- [x] 직무, 경력, 채용 유형, 지역, 기업 규모 필터가 조합 조건으로 동작한다.
- [x] 기간 필터 `오늘`, `7일`, `30일`, `기간 전체`이 게시일 기준으로 동작한다.
- [x] `추천순`, `최신순`, `조회순` 정렬이 선택값에 맞게 목록 순서를 바꾼다.
- [x] 활성 필터 칩 삭제 시 해당 조건만 초기화된다.

## Phase 3 - 상세 드로어

- [ ] 구현 PR 브랜치가 `feature/user-jobNotice-detail-flow` 또는 같은 패턴의 Phase 전용 브랜치다.
- [ ] 카드 클릭 시 선택한 공고의 상세 드로어가 열린다.
- [ ] 카드에서 Enter/Space 키를 눌러도 상세 드로어가 열린다.
- [ ] 상세 API 호출은 `frontend/src/user/api` 하위 모듈을 통해 수행된다.
- [ ] 상세 드로어는 목록 요약 정보 또는 상세 로딩 상태를 즉시 표시한다.
- [ ] 상세 조회 성공 시 회사명, 공고 제목, 경력, 고용 형태, 근무 지역, 마감일, 출처가 표시된다.
- [ ] 상세 조회 성공 시 기술 스택 또는 태그 fallback이 표시된다.
- [ ] `공고 상세` 탭에 담당 업무, 자격 요건, 우대 사항, 전형 절차, 근무 조건, 마감 정보가 표시된다.
- [ ] `기업 정보` 탭에 회사명, 업종, 기업 규모, 기업 소개가 표시된다.
- [ ] 상세 조회 실패 시 목록은 유지되고 드로어 내부에 오류 안내와 재시도 또는 닫기 액션이 표시된다.
- [ ] 상세 필드 일부가 비어 있어도 깨진 문자열이나 빈 섹션만 남지 않는다.
- [ ] 상세 드로어 닫기 버튼, 오버레이 클릭, Escape 키 닫기가 모두 동작한다.
- [ ] 상세 드로어가 닫히면 선택 공고 상태가 초기화된다.

## Phase 4 - 스크랩과 원본 이동

- [ ] 구현 PR 브랜치가 `feature/user-jobNotice-bookmark-sync` 또는 같은 패턴의 Phase 전용 브랜치다.
- [ ] 북마크 버튼 클릭은 상세 드로어를 열지 않는다.
- [ ] 스크랩 API 호출은 `frontend/src/user/api` 하위 모듈을 통해 수행된다.
- [ ] 스크랩 성공 후 목록 카드와 상세 드로어의 북마크 아이콘 상태가 동일하다.
- [ ] 스크랩 실패 시 이전 상태로 되돌아가며 실패 안내가 제공된다.
- [ ] 비로그인 사용자의 스크랩 시도는 로그인 필요 안내 또는 `/auth/login` 이동으로 이어진다.
- [ ] 원본 공고 버튼은 `originalUrl`이 있으면 해당 URL을 새 탭으로 연다.
- [ ] `originalUrl`이 없으면 공고 제목 기반 검색 URL fallback을 사용한다.
- [ ] 원본 이동 URL을 만들 수 없으면 버튼 비활성화와 안내 문구가 제공된다.

## Phase 5 - UI, 접근성, 검증

- [ ] 구현 PR 브랜치가 `feature/user-jobNotice-accessibility-qa` 또는 같은 패턴의 Phase 전용 브랜치다.
- [ ] 360px 모바일 화면에서 검색, 필터, 카드, 정렬, 상세 드로어, 하단 액션 버튼 텍스트가 겹치지 않는다.
- [ ] 720px 이하에서 공고 카드는 한 열로 표시된다.
- [ ] 1080px 이하에서 필터 패널은 본문 위 또는 한 열 흐름으로 자연스럽게 배치된다.
- [ ] 상세 드로어는 모바일 화면에서 화면 밖으로 주요 액션이 밀려나지 않는다.
- [ ] 모든 아이콘 버튼은 `aria-label` 또는 보이는 텍스트로 목적을 알 수 있다.
- [ ] 상세 드로어는 `role="dialog"`와 `aria-modal="true"`를 가진다.
- [ ] 상세 드로어가 열린 동안 배경 스크롤이 잠긴다.
- [ ] 키보드만으로 검색, 필터, 정렬, 카드 진입, 상세 탭 전환, 스크랩 토글, 원본 이동, 상세 닫기를 수행할 수 있다.
- [ ] 상단 이동 버튼은 페이지 최상단으로 부드럽게 이동한다.
- [ ] 프로젝트 표준 빌드 또는 타입 검증 명령이 통과한다.
