# Feature Specification: Community

**Feature Branch**: `007-community`
**Status**: Draft

## User Scenarios & Testing

### User Story 1 - 게시글 목록 조회 (Priority: P1)

> 사용자는 취업 관련 정보와 경험을 확인하기 위해 커뮤니티 게시글 목록을 조회한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 커뮤니티 페이지에 접근했을 때, **When** 게시글 데이터가 존재하면, **Then** 게시글 목록이 최신순으로 표시된다.
2. **Given** 사용자가 게시글 목록을 보고 있을 때, **When** 특정 게시글을 클릭하면, **Then** 게시글 상세 페이지로 이동한다.
3. **Given** 게시글 데이터가 존재하지 않을 때, **When** 사용자가 커뮤니티 페이지에 접근하면, **Then** 게시글이 없다는 안내 메시지가 표시된다.

---

### User Story 2 - 게시글 검색 및 카테고리 필터 (Priority: P1)

> 사용자는 원하는 정보를 빠르게 찾기 위해 게시글 검색 및 카테고리 필터를 사용한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 검색어를 입력했을 때, **When** 제목 또는 내용에 검색어가 포함된 게시글이 존재하면, **Then** 해당 게시글만 표시된다.
2. **Given** 사용자가 특정 카테고리를 선택했을 때, **When** 해당 카테고리 게시글이 존재하면, **Then** 선택한 카테고리 게시글만 표시된다.
3. **Given** 검색 결과가 없을 때, **When** 검색을 수행하면, **Then** 검색 결과가 없다는 안내 메시지가 표시된다.

---

### User Story 3 - 인기 게시글 확인 (Priority: P2)

> 사용자는 다른 사용자들이 많이 본 게시글을 확인하기 위해 인기 게시글 영역을 조회한다.

**Acceptance Scenarios**:

1. **Given** 인기 게시글 데이터가 존재할 때, **When** 사용자가 커뮤니티 페이지에 접근하면, **Then** 인기 게시글 영역이 표시된다.
2. **Given** 게시글 좋아요 수 데이터가 존재할 때, **When** 인기 게시글을 계산하면, **Then** 좋아요 수 기준으로 정렬된다.
3. **Given** 인기 게시글이 존재하지 않을 때, **When** 페이지에 접근하면, **Then** 기본 안내 문구가 표시된다.

---

### User Story 4 - 게시글 북마크 및 사용자 인터랙션 (Priority: P2)

> 사용자는 관심 있는 게시글을 저장하기 위해 북마크 기능을 사용한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 게시글 목록을 보고 있을 때, **When** 북마크 버튼을 클릭하면, **Then** 북마크 상태가 변경된다.
2. **Given** 사용자가 북마크 버튼을 클릭했을 때, **When** 이벤트가 발생하면, **Then** 게시글 상세 페이지로 이동하지 않는다.
3. **Given** 사용자가 키보드로 게시글 카드에 접근했을 때, **When** Enter 또는 Space 키를 입력하면, **Then** 게시글 상세 페이지로 이동한다.

---

### User Story 5 - 인증 기반 글쓰기 기능 (Priority: P1)

> 사용자는 자신의 경험과 정보를 공유하기 위해 게시글을 작성한다.

**Acceptance Scenarios**:

1. **Given** 사용자가 로그인 상태일 때, **When** 커뮤니티 페이지에 접근하면, **Then** 글쓰기 버튼이 표시된다.
2. **Given** 사용자가 비로그인 상태일 때, **When** 커뮤니티 페이지에 접근하면, **Then** 글쓰기 버튼이 표시되지 않는다.
3. **Given** 사용자가 글쓰기 버튼을 클릭했을 때, **When** 권한이 확인되면, **Then** 게시글 작성 페이지로 이동한다.

---

### Edge Cases

* 게시글 데이터가 없는 경우 어떤 빈 상태 UI를 보여줄 것인가?
* 인기 게시글 데이터가 없는 경우 어떤 안내 문구를 표시할 것인가?
* 검색 결과가 없는 경우 어떤 빈 상태 UI를 표시할 것인가?
* 작성자 정보가 누락된 게시글은 어떻게 표시할 것인가?
* 좋아요 수 또는 댓글 수가 없는 경우 기본값을 표시할 것인가?
* 존재하지 않는 게시글 상세 페이지에 접근했을 때 어떻게 처리할 것인가?
* 로그인 토큰 정보가 누락된 경우 글쓰기 버튼을 어떻게 처리할 것인가?

## Requirements

### Functional Requirements

* **FR-001**: 시스템은 게시글 목록을 조회할 수 있어야 한다.
* **FR-002**: 시스템은 게시글 상세 정보를 조회할 수 있어야 한다.
* **FR-003**: 시스템은 게시글을 카테고리별로 필터링할 수 있어야 한다.
* **FR-004**: 시스템은 게시글 제목 및 내용 기반 검색을 제공해야 한다.
* **FR-005**: 시스템은 좋아요 수 기반 인기 게시글을 제공해야 한다.
* **FR-006**: 시스템은 게시글 북마크 기능을 제공해야 한다.
* **FR-007**: 시스템은 로그인 사용자에게만 글쓰기 기능을 제공해야 한다.
* **FR-008**: 시스템은 키보드 접근성을 지원해야 한다.
* **FR-009**: 시스템은 게시글 데이터를 커서 기반 목록 형태로 조회할 수 있어야 한다.
* **FR-010**: 시스템은 백엔드 API 연결 전까지 mock data를 사용하여 화면을 구성할 수 있어야 한다.

### Key Entities

* **CommunityPost**

    * `id`: 게시글 고유 ID
    * `category`: 게시글 카테고리
    * `title`: 게시글 제목
    * `preview`: 게시글 요약 내용
    * `author`: 작성자
    * `createdAt`: 작성일
    * `views`: 조회수
    * `likes`: 좋아요 수
    * `comments`: 댓글 수
    * `bookmarked`: 북마크 여부
    * `hot`: 인기 게시글 여부
    * `reportCount`: 신고 수

* **CommunityCategory**

    * `전체`
    * `질문`
    * `면접 후기`
    * `이력서 팁`
    * `합격 후기`
    * `자유`

* **PopularPost**

    * `id`: 게시글 ID
    * `title`: 게시글 제목
    * `likes`: 좋아요 수

## Success Criteria

* **SC-001**: 사용자는 게시글 목록을 정상적으로 조회할 수 있다.
* **SC-002**: 사용자는 게시글 상세 페이지로 이동할 수 있다.
* **SC-003**: 사용자는 카테고리별 게시글을 조회할 수 있다.
* **SC-004**: 사용자는 검색 기능을 통해 원하는 게시글을 찾을 수 있다.
* **SC-005**: 사용자는 인기 게시글 목록을 확인할 수 있다.
* **SC-006**: 사용자는 게시글을 북마크할 수 있다.
* **SC-007**: 로그인 사용자는 글쓰기 버튼을 확인할 수 있다.
* **SC-008**: 비로그인 사용자는 글쓰기 버튼을 볼 수 없다.
* **SC-009**: 데이터가 없거나 일부 누락되어도 화면이 깨지지 않는다.
* **SC-010**: 기존 사용자 페이지와 관리자 페이지의 동작에 영향을 주지 않는다.

## Assumptions

* Community는 사용자 페이지 기준 기능으로 구현한다.
* 적용 모듈은 `user-backend`, `user-frontend`를 기준으로 한다.
* 현재 프론트엔드 구현 단계에서는 백엔드 API가 완성되지 않았을 수 있으므로 mock data를 우선 사용한다.
* 실제 게시글 저장, 수정, 삭제 기능은 백엔드 API 명세가 확정된 후 연동한다.
* 로그인 인증 및 권한 검증은 기존 인증 구조를 따른다.
* 관리자 페이지, 신고 처리 로직, 댓글 관리 기능은 현재 작업 범위에서 제외한다.
