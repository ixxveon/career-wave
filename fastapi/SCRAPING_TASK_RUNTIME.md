# 스크래핑 백그라운드 작업 운영 정책

## 현재 MVP 운영 정책

- 관리자 스크래핑 작업은 FastAPI 워커 프로세스 안에서 `asyncio.create_task()`로 실행합니다.
- FastAPI 서비스는 단일 워커로 실행합니다. 예: `uvicorn main:app --workers 1`
- 서비스 종료 시 새 스크래핑 작업 등록을 막기 위해 자동 실행 스케줄러를 먼저 중단합니다.
- 종료 중에는 추적 중인 스크래핑 작업이 끝날 때까지 최대 15초 동안 대기합니다.
- 대기 시간을 넘긴 작업은 pending 상태로 로그에 남깁니다. 현재 스크래핑은 `asyncio.to_thread()`로 동기 작업을 실행하므로, 강제 취소를 안전한 작업 중단으로 간주하지 않습니다.

## 현재 범위와 후속 확장 기준

- 현재 메모리 기반 task registry는 프로세스 재시작 뒤 작업 상태를 복구하지 않습니다.
- 멀티 워커 실행, 분산 작업 상태, 재시도, 취소, 인스턴스 간 상태 조회가 필요하면 별도 작업 큐 또는 DB 기반 scraping job 모델이 필요합니다.
- 해당 외부 작업 모델을 도입하기 전에는 스크래핑 실행을 위해 FastAPI 워커 수를 늘리지 않습니다.
